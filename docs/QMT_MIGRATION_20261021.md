# 华泰 QMT 内置运行迁移方案

日期：2026-10-21。状态：设计与阻断项梳理，未部署，未启用真实委托。

后续决策：用户明确否决QMT内部运行策略；本文件仅作调研档案，不再是实施路线。当前策略留在MoneyMore，实时行情转向AlphaFeed，参见ALPHAFEED_ACCEPTANCE_20261021.md与PLAN.md最新决策。不要据下文继续建设内置迁移。

## 1 结论

将 QMT 从外部行情和交易网关改为内部策略运行平台。MoneyMore 保留研究、训练、历史模拟、既有账本和网页；面向实盘的策略必须在 QMT 内部独立取得获准数据、计算信号、执行风控和管理交易状态。

这不是把原 subprocess 桥改一个端口。按内部文档的边界，个人账户不能把外部 MoneyMore 的目标组合通过文件、HTTP、TCP、数据库或其他变相外接渠道自动传入 QMT；也不能默认把 QMT 内部行情、成交通过这些方式自动传出给 MoneyMore。

现有研究策略不自动等同于可部署策略。两端应复用经过审计的纯计算逻辑和协议，不强行复用当前进程、存储和调度实现。数据和模型无法取得等价部署许可时，该策略保持研究状态，不静默删减后冒充迁移完成。

- 第8条公告：关闭策略本地文件读写，关闭外部网络、本机及局域网数据库连接；个人和普通机构关闭 MiniQMT 独立交易入口。
- 开头第8、9问：仅使用迅投内部接口的策略具备迁移方向；涉及外部交互的策略可能需要重写。

文档没有提供新版交易初始化代码、完整支持库清单、Python版本要求、模型导入方法或跨系统结果导出协议。这些是待验证项，不以旧SDK示例补全猜测。文档也没有保证全部数据免费、没有请求限制。

## 5 目标服务链路

```text
研究运行面
授权研究数据 → MoneyMore数据仓库 → 因子与GPU训练 → 历史模拟与候选评估
                                          → 本地数据库 → API → Dashboard

QMT运行面
QMT内置行情与财务 → 同版本纯计算核 → 全局目标组合 → 仓位控制
                                                  → 开盘或日内执行
                                                  → 官方账户与成交回报
                                                  → 内部对账与恢复

两面之间不预设自动网络或文件通道
代码或模型的发布与结果归档需使用券商明确允许的产品功能
```

代码发布是经过审核的版本部署，不是盘中不断注入外部交易信号。是否允许上传模型、安装依赖、导入参数及如何归档运行结果，均须按券商明确支持的功能验收；不能把“人工复制一份代码”扩展成每日自动注入信号。

若自动实时观测和外部GPU模型周期更新无法获得允许，则必须接受观测或模型发布的限制，或重新选择符合个人准入条件的官方产品。不能承诺保留现有所有功能且完全无缝。

## 6 模块接口与实现原则

### 数据适配

- 定义宿主无关的行情、复权、交易日历、标的状态、公司行为、财务点时数据协议。
- QMT端只调内部官方接口；研究端可继续现有数据源。分别记录来源、可用时间、调整口径、单位和完整性。
- 大池历史下载与持仓实时订阅分开；不得给1000只标的的所有周期盲目全量订阅。
- 每个下载批次有数量与时间范围上限、增量水位、失败熔断；交易时段不执行大规模历史回填。
- 分钟完整性按交易时段、停牌与真实交易日校验，不仅以条数大于200判断；无数据时禁止填充为虚假成交。
- Top1000股票池、市值和基本面因子需逐字段对照；不能以少数行情字段替换原基线所需数据。

### 策略纯计算核

- 输入为已标准化的内存数据、上一目标及已确认持仓；输出为分数、目标权重、风控决策和原因。
- 保留全池排名、置信度权重、Top-K缓冲、整手约束、仓位控制等现有协议，不重新引入行业等预算。
- 研究与QMT宿主分别处理数据取得和状态保存；核心不能读YAML、调用HTTP或直接操作SQLite。
- 不在内置回调中执行训练、阻塞sleep、等待循环或整池耗时回填。

### 交易与恢复

- 先查明内置交易入口；不假定需要XtQuantTrader(path).connect，不替换认证参数或路径碰运气。
- 用可见账户列表、账户类型、登录状态和账户匹配验收访问权限。只读查询失败是硬阻断，不通过真实买单验证连接。
- 引入执行适配层，区分QMT模拟信号、获准仿真柜台和真实资金账户，不能把模拟信号当柜台成交。
- 同一真实账户多个策略共享资金与持仓时，需单一执行协调器、虚拟子账本和净额分配规则。不能照搬多个模拟账户各用100%资金的独立账本。
- 下单意图、已报委托、成交、拒单与未知状态分别管理；故障恢复先查未完成订单和成交，再按最新目标差额决定下一步。
- 原execution_continuity.py的决策和幂等语义可复用；持久化后端需在QMT许可范围内重新实现。
- 本机新版config/fun.xml已列出get_py_key(key)与save_py_key(key,value)：前者返回(value,errid,errmsg)，后者返回(errid,errmsg)。这是优先验证的服务器端状态保存方案，不需要策略写本机SQLite。接口出现在本地说明中不等于账户已获使用权限；仍需验证账号隔离、容量、原子性和重启恢复，不能把它当成跨系统信号通道。若不能可靠持久化，则不能通过实盘验收。
- 实盘不补造过去成交；模拟历史估算回放独立标记，不纳入真实账户对账。

### 深度学习

- GPU训练仍可在本地研究环境运行，但“训练完成后自动同步模型至QMT”目前没有获准链路，必须标为未解决。
- 必须确认允许的模型发布与加载机制，再选择兼容推理实现；不能利用日志、共享内存、编码脚本轮询等途径规避外接限制。
- 现有模型涉及pickle、Qlib封装、12维特征、多种子GRU及LightGBM融合；不能用一个随机GRU前向成功代替整个模型验收。
- 若无法等价迁移某模型，保留研究账户和历史，QMT部署账户标记“不支持部署”，不得退回简单均线却沿用原模型名称。

### 网页观测

- Dashboard必须同时显示“研究结果”和“QMT执行状态”的来源、时间、模式及是否同步。
- 没有允许的结果获取渠道时，QMT卡片显示“尚无获准同步渠道”，不读取QMT日志作为连续数据桥。
- 手工导入对账仅在券商明确提供且允许导出的功能下规划；否则保持阻断，不能默认可导出交易或行情文件。
- 诊断阶段本地读取日志与持续生产化日志转发不同；本方案不把既有诊断读取扩展为长期对接方案。

## 7 建设顺序与验收门禁

### M10.1 运行方式与能力矩阵

核实华泰版本、真正加载的库和内置初始化示例；先完成账户只读访问。列出每个接口的运行位置、权限、数据范围、是否持久化和故障行为。停用旧MiniQMT恢复链路的变更需单独实施并验证不影响API/Web。

验收：无端口式外接；账户明确匹配；行情时效和历史完整性通过；没有认证重试风暴。现状：仅行情部分通过，账户仍阻断。

### M10.2 计算核拆分和等价测试

冻结一个现有基线协议，提取纯计算逻辑，以固定输入验证两宿主的分数、排序、权重和风险决策。按库兼容性处理3.6限制，不要求原服务器整体改成3.6。

验收：确定性排序与原因一致、数值误差阈值预先规定；原策略历史与收益不重刷。现状：待建。

### M10.3 基线内部仿真闭环

先迁移一个基线；再叠加pysystemtrade仓位和日内执行，使用相同基线目标生成逻辑。研究模拟账本保留，新增部署账户按独立版本观察。

验收：信号、委托、成交回报、T+1、整手、费用、拒单、重启恢复和资金持仓对账可审计。没有可用仿真柜台时，模拟信号模式只算部分通过。现状：待建。

### M10.4 模型部署与观测渠道

确认GRU/LightGBM模型发布、依赖和加载许可；确认官方结果获取方式。前者未通不迁深度学习账户，后者未通不承诺现有dashboard自动实时显示QMT执行。

验收：固定版本特征和模型输出等价、部署可回滚、观测来源真实且无未批准通道。现状：阻断。

### M10.5 守护与连续性演练

守护只检查当前正确客户端、策略运行和获准状态，不反复登录或启动被关闭入口。演练网络中断、客户端退出、跨日重启、未知订单、重复回报、持久化故障及分红除权。

验收：禁止重复委托，未知状态冻结新增风险；恢复不改写历史；至少20个交易日无阻断级故障且对账通过。现状：待建。

### M10.6 实盘启用评审

仅在所有前置门禁完成后提出评审。真实账户、资金上限、允许策略、最大委托额、紧急停机与人工授权逐项确认。本方案和只读测试不是实盘授权。

## 8 本次改动边界

本次仅建立适配方案和规划入口；未停止或启动服务、未修改计划任务、未迁移既有账户、未重算收益、未发送委托，也未声称已恢复QMT账户接口。

最优先的未决问题是华泰内置交易库的正确初始化方式，其次是模型发布和观测结果取得方式。在这些问题未明确前，不继续让用户反复粘贴猜测性脚本。
