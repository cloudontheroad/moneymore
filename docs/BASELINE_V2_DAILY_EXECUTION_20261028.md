# 基线V2：持仓退出分类与正式日度回放接通

## 分类规则

只在具有对应日期完整、唯一身份Top1000清单时，才能确认“退出候选池”。不能仅凭分数表找不到股票就判为淘汰。

| 实际持仓状态 | 决策 | 数据与交易约束 |
| --- | --- | --- |
| 仍在候选池且可评分 | 复用正式留存/排名/相关性规则 | 持仓来自隔离模拟账户实际成交，不来自昨日目标 |
| 完整候选池明确不含该股票 | 强制退出候选池 | 继续保留持仓行情和公司行为数据；必须有已核验成交证据，可卖时才执行，不能虚构清仓 |
| 池内但必需评分数据缺失 | 全组保护并告警 | 清除旧目标；下一开盘不能误执行旧信号；不把数据故障当卖出理由 |
| 无完整候选池证据 | 视为输入故障 | 默认保护规则不变，不根据缺分猜测退出 |

候选池强制退出不占主动排名换股上限；主动换股仍沿用最大3只，原相关性约束强制退出语义不改。最终下单数量仍通过现金、费用、整手、仓位、停牌及涨跌停约束求解。退出意图不等于已成交，卖不掉时实际仓位仍保留并参与下次构建。

这些规则只接入隔离研究回放。线上原基线、旧候选账户及其账本不改，原V2原型仍暂停。

## 正式构建器与实际账户

研究模块`baseline_v2_daily_replay.py`复用`global_topk_portfolio`：Top10、退出排名15、主动替换最多3只、rank_linear、原相关性门槛与仓位上下限。每天收盘使用该隔离PaperBroker账户实际持仓（含已生效但未上市股份权利），构建次日目标；次日开盘只接收open/can_buy/can_sell，不读取当日收盘或高低价。

复用原整数成本规划器、PaperBroker与公司行为应收/入账逻辑。不是提前算好理想持仓后强行每天重置，也不是月度等权实验改名。持仓评分缺失仍保护；没有删除原安全门禁。

## 验证与剩余建设

46项相关测试通过，包括：完整池外退出与池内数据故障区分、缺完整清单时默认保护、实际成交持仓驱动、退出股真正卖出、故障清除旧目标且下一日无误交易、原整数执行及月度回放兼容性。

剩余：按日期扩大正式回放与实际持仓所需证据，补齐新增标的后继续；覆盖真实历史退池、输入保护、停牌跨日和公司行为；完成两年配对账本、成本/换手与逐年风格归因。完整联合池复权经济性、财务原始版本和学习权重稳健性门禁仍保留，不恢复候选V2交易。

## 命令

默认短窗口：`.venv/Scripts/python.exe scripts/replay_baseline_v2_daily.py`

扩大前缀窗口：`.venv/Scripts/python.exe scripts/replay_baseline_v2_daily.py --end YYYYMMDD`。仍从2024-01-31初始现金重建，不拼接不同试验的收益；遇未核验标的停止并列出缺口。

补最新中止运行明确列出的1—8只股票：`.venv/Scripts/python.exe scripts/extend_baseline_v2_daily_execution.py`，上限32请求。它不是自动无限补数器。

最新状态：`daily-inputs/daily-replay.json`。各轮都有独立SQLite、收盘决策、开盘规划、行情、成交与逐日对账文件。服务无需重启，未创建Codex自动任务或发送真实委托。
