## 1. 项目目标

MoneyMore 是面向个人投资者的 A 股量化研究与模拟交易系统。当前阶段不接入程序化实盘交易，重点是建立一条可审计、可复现、可持续运行的研究链路：

```text
点时数据 → 因子注册表 → 横截面预测分数 → Top-K组合
       → Qlib risk_degree择时 → 风险约束 → 次日开盘模拟撮合
       → 成交对账 → 前瞻证据归档 → 前台观测
```

系统以 Qlib 的分层思想和策略接口为主体，但保留 MoneyMore 自己的 A 股数据、撮合、账本和服务端实现：

- Qlib负责定义研究范式：特征、预测分数、组合策略、动态风险度、回测评价和模型治理；
- MoneyMore负责点时数据、A股交易规则、模拟订单、持仓账本、每日流水线和产品页面；
- 后续模型可以接入原生Qlib训练器，不改变组合、执行和观测接口。

当前只运行 `PAPER_ONLY` 模式。券商接口不在本阶段范围内。

## 2. 核心架构

### 2.1 数据层

- Tushare为当前主数据源；
- 原始响应按来源、表名和批次不可变保存到 `data/raw`；
- 去重后的研究表保存到 `data/processed`；
- 财务数据按公告可用日期进入因子，禁止按报告期回填未来信息；
- 复权价格用于信号，未复权开盘价用于模拟成交；
- 历史股票池保留当期成员，降低幸存者偏差；
- ETF权限尚未开通，当前研究范围是A股个股。

### 2.2 因子与预测分数

因子体系采用Qlib式“特征注册—统一预处理—横截面评价”流程：

- 因子注册表目前包含21个价格、估值、基本面和分红因子；
- 低值更优因子统一反向；
- 每个交易截面执行去极值和标准化；
- 使用Rank IC、ICIR和分层收益评估；
- 样本内与样本外分别报告；
- 2022年后的历史已参与开发判断，不能再称为纯净测试集。

当前银行模型：

```text
bank_multifactor_no_quality_candidate

价值      47.0588%
防御      29.4118%
动量      23.5294%
质量       0%
```

质量组暂时保留在注册表和报告中，但在当前候选模型中权重为零。

### 2.3 Top-K组合策略

Top-K本身属于交易策略，而不只是选股列表。它规定：

- 调仓频率：按研究日历生成截面信号；
- 目标数量：Top 8；
- 持仓缓冲：持仓排名未跌出12名时允许继续持有；
- 换仓限制：每期最多正常替换2只；
- 基础单股权重：银行子账户10%；
- 基础组合风险度：80%；
- 成交时点：T日收盘后生成目标，T+1开盘模拟成交。

Top-K回答“买卖哪些股票”。组合总体是否使用80%风险预算，由Qlib式 `risk_degree` 择时层回答。

### 2.4 Qlib式交易择时

MoneyMore采用与Qlib `BaseSignalStrategy.get_risk_degree()`一致的语义：

```text
risk_degree = 投入风险资产的组合资金比例
```

最终单股目标权重：

```text
最终单股权重 = Top-K基础权重 × risk_degree ÷ 基础风险度
```

已建立三个同口径基线：

1. `fixed_80`
   - 固定风险度80%；
   - 作为不择时对照组。

2. `kama_10_2_30`
   - Kaufman自适应移动平均线的多头/现金切换；
   - 历史结果明显劣化；
   - 仅保留为被拒绝基线，不作为当前模拟策略。

3. `vol_target_12`
   - 60日实现波动率；
   - 年化目标波动率12%；
   - 风险度限制为20%～80%；
   - 以10个百分点为台阶，每20个交易日重新评估；
   - 当前状态为 `PROSPECTIVE_CANDIDATE`。

历史对比：

| 策略 | 区间 | CAGR | 最大回撤 | 夏普 |
|---|---|---:|---:|---:|
| fixed_80 | 样本内 | 1.62% | -25.68% | 0.18 |
| fixed_80 | 样本外 | 10.31% | -14.81% | 0.93 |
| kama_10_2_30 | 样本内 | -2.93% | -26.70% | -0.11 |

### 2.5 风险与权重优化

当前阶段采用：

- Top-K等权；
- 单股基础权重10%；
- 基础总风险度80%；
- `risk_degree`动态缩放；
- 组合最大回撤熔断；
- 交易费用、滑点、整手和涨跌停限制。

后续可在Top-K之后增加Qlib增强指数或Riskfolio风险预算模块，比较：

- 等权；
- 逆波动；
- 风险平价；
- 换手约束下的最小方差。

权重优化必须作为独立实验，不与选股和择时参数同时搜索。

### 2.6 模拟撮合与对账

PaperBroker使用独立账户 `bank_shadow`：

- 决策、委托、成交、持仓和现金分别记账；
- T日信号不允许T日成交；
- T+1开盘价加滑点撮合；
- 买入按100股整手；
- 计算佣金、最低佣金、印花税和过户费；
- 涨跌停或不可交易状态阻止对应方向成交；
- 每日完成订单、成交、现金和持仓对账；
- 对账不一致时流水线失败关闭。

## 3. 模型治理

模型状态统一为：

- `RESEARCH_ONLY`：仅供研究展示；
- `PROSPECTIVE_CANDIDATE`：参数冻结，开始累计前瞻证据；
- `PAPER_QUALIFIED`：达到模拟主策略门槛；
- `SUSPENDED`：数据、运行或表现异常，停止新增目标。

当前状态：

| 模块 | 状态 |
|---|---|
| 银行多因子V1 | `RESEARCH_ONLY` |
| 去质量组Top-K候选 | `PROSPECTIVE_CANDIDATE` |
| KAMA择时 | `REJECTED_BASELINE` |
| 12%波动率目标择时 | `PROSPECTIVE_CANDIDATE` |
| 银行影子账户 | `PAPER_ONLY` |

晋级原则：

- 参数和代码冻结后才开始计算前瞻表现；
- 至少覆盖一个完整调仓周期；
- 流水线、成交和对账不存在未解释差异；
- 与固定风险度基线比较收益、回撤、夏普和换手；
- 不允许只因历史收益较高而晋级；
- 修改核心因子、权重、择时参数或成交规则后重新开始证据周期。

## 4. 每日流水线

服务端每天18:30（Asia/Shanghai）运行，不依赖Codex自动任务：

1. 校验交易日；
2. 增量同步行情、估值、财务和分红数据；
3. 撮合前一交易日待执行委托；
4. 计算21因子并生成银行横截面分数；
5. 执行Top-K、Rank 12缓冲和最多2只替换；
6. 计算当前 `risk_degree`；
7. 生成下一交易日目标委托；
8. 完成现金、持仓、订单和成交对账；
9. 将不可变运行报告写入 `state/bank-shadow`；
10. 前台刷新组合、择时、订单和流水线状态。

   - 交易时段QMT行情延迟超过120秒、守护心跳失联、账本损坏或账户对账不一致时自动冻结新撮合；

   - 本地守护器每10秒写入原子心跳，API或Web异常退出后自动拉起，并把重启事件写入JSONL审计日志。

3. **M8.3 备份与恢复演练——待建设**
   - 对SQLite账本、策略状态和关键Parquet清单执行版本化备份；
   - 定期验证备份可读性，并在隔离目录完成恢复演练；
   - 实盘启用前要求至少20个交易日无阻断级故障。

4. **M8.4 交易连续性与正式补偿——核心规划器已建，券商执行适配待建设**
   - 故障期间冻结新委托；恢复后先从券商重新查询资金、持仓、当日成交和全部未完成委托，连续两次确认且对账一致才生成补偿计划。
   - 历史模拟盘可用注明来源的分钟线估算回放；实盘永不补造历史成交，也不把旧日委托原样重发。只以**最新生效策略目标 − 券商真实持仓**计算当前差额。
   - 存在未完成或结果不明的券商委托时，先查询/撤单并等待最终状态；成交回报未确认前不重复提交。补偿委托采用持久化幂等流水，未知状态禁止盲目重发。
   - 先卖后买，卖出仅限券商可卖数量；卖出成交后重新查询资金与持仓，禁止预支预计卖出款。涨跌停、整手、实时行情时效、交易时段及账户风险状态继续约束执行。
   - 已落地 `execution_continuity.py` 的只读规划器与 `RecoveryJournal` 幂等预约；目前系统仍是 `PAPER_ONLY`，不连接实盘交易接口，不自动发送券商委托。
   - 待建：华泰交易账户只读快照适配、订单/成交回报映射、撤单确认与未知回报恢复、受限自动提交开关、故障注入与至少20个交易日的模拟验证；上述完成前不得启用实盘自动补偿。

### M9 总股票仓位研究联赛

> 旧版人工合成模型、skfolio、FinRL和DeepDow均已退出有效展示；市场与仓位页保留pysystemtrade主线，并以三个独立前瞻账户比较原版波动率目标、非对称降险/加仓和趋势上限三种总仓位策略。选股、费用与撮合口径一致，差异只来自总股票仓位信号。

1. **M9.1 统一输出协议——已完成**
   - 四条方法线统一只输出`target_exposure`，取值限定为0～1；
   - 禁止输出股票代码、行业、个股权重或任何选股字段，保证仓位研究与选股正交；
   - 输入暂限定为抽象股票组合收益和现金收益；如何接入现有策略明确留到后续阶段；
   - 未完成原生适配或训练的模型必须返回`NOT_TRAINED`，禁止用临时公式伪造结果；
   - 当前叠加结果以独立反事实曲线展示，不修改原基线账本；T日收盘仓位信号严格从下一交易日起作用。

2. **M9.2 pysystemtrade风险目标适配——已完成首版**
   - 按原项目的percentage volatility target、资本缩放、相关风险和position buffering口径实现；
   - 固化上游版本、配置摘要、训练截止日及逐日决策产物。
   - 当前忠实采用上游默认16%年化波动目标、35日快速EWMA、10年慢波动、30%慢波动混合和10%仓位缓冲；唯一A股本地约束是禁止杠杆、总股票仓位上限100%；
   - 适配器只输出总股票仓位，不读取股票代码、行业或选股分数；已与基线组合收益流形成正交叠加对照。

3. **M9.3 skfolio风险资产/现金分配——已完成首版**
   - 使用原生`MeanRisk(MAXIMIZE_UTILITY, VARIANCE)`，股票代理预算约束为0～100%，未投资预算自然形成现金，不把零方差现金列强塞进协方差矩阵；
   - 以120/20日Walk Forward、1日purge完成顺序样本外选型，并以6折/2测试折CPCV及1日purge/embargo输出路径稳健性诊断，不使用随机K折；
   - 风险厌恶只在预注册的2/5/10/20/50宽网格中选择，样本外评价风险厌恶固定为10，避免每条路径改变评分偏好；
   - 换仓成本采用当前系统买卖成本的平均单边近似0.061%，最终拟合把前一日仓位传入skfolio原生交易成本项；
   - 当前仍只输出一个`target_exposure`，不接触股票代码、行业、因子排名或GRU分数。
   - 验收结论：现金偏好长期压低仓位，且未证明相对朴素基准具有经济有效性；已退出API有效/审计展示与前台，不再参与后续PK。

4. **M9.4 FinRL总仓位智能体——已完成首版**
   - 动作空间严格压缩为单一总股票仓位，剩余权重自动归入现金；
   - 禁止环境接收股票代码、行业或个股预测分数；训练、验证、测试与前瞻期完全隔离。
   - 训练频率固定为每周六09:00，每个交易日只执行推理；服务错过训练时启动补跑，失败最多重试3次、间隔6小时；候选模型不得自动晋级。
   - 采用FinRL的train-validation-test-trade分层和Stable-Baselines3 PPO；状态仅含20日滞后市场代理收益、波动、回撤及上一仓位，动作严格为一个0～1总股票仓位；
   - 每周以17/42/101三个随机种子各训练20000步，验证集Sharpe选型、独立测试集留证，随后用当时全部可见数据重训优胜配置供未来推理；
   - FinRL拥有独立调度数据库与日志目录，不与Qlib GRU互相覆盖；一维MLP固定CPU训练，避免Stable-Baselines3已知的GPU低利用率和额外开销。

5. **M9.5 DeepDow总仓位网络——已完成首版**
   - 输出层只允许风险资产/现金二元权重，并由风险资产权重形成`target_exposure`；
   - 使用原生可微分配置与风险损失，保存随机种子、模型权重和完整训练日志。
   - 输入严格为`(batch, 3 channels, 60 lookback, 2 assets)`，两资产仅为Top1000等权股票代理与现金；卷积特征提取后采用DeepDow 0.2.3分析式SoftmaxAllocator同公式输出二元权重；
   - 采用DeepDow SharpeRatio同公式训练20日未来收益，17/42/101三个种子、100轮、CUDA可用时启用GPU，按时间顺序切分训练/验证/独立测试并保存权重、损失尾部与完整指标；
   - 因DeepDow包在Windows强制导入未使用的`cvxpylayers/diffcp`且缺少预编译轮子，本项目采用官方纯PyTorch源码兼容子集，不安装无关Visual C++编译链，并在产物中明确记录兼容方式；
   - 首轮三个种子均出现接近100%股票权重，确认Sharpe损失对“风险资产+零收益现金”的仓位缩放近似不敏感；产物保留为重要否证样本并标记`SATURATED_FULL_EXPOSURE`，生产门禁固定不通过，不把全仓输出解释为有效择时。
