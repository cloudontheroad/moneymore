# 候选生命周期 v1

生效：2026-10-26。只作用于独立Qlib模拟候选，不修改生产基线或主挑战者，不产生真实委托。

## 规则

1. 当前研究门禁不通过：`GATE_REJECTED`，归档，保留具体门禁失败项。
2. 20、40个可信共同日：与因子基线和主GRU分别作净权益配对检验，复用现有 `evaluate_paired_performance`。5日分块bootstrap、2000次固定种子抽样，Bonferroni校正候选数量×3检查点×2对照。置信上界均小于零且风险调整收益均更差，才 `EARLY_REJECTED`；否则继续。未过首个检查点不因收益落后淘汰。
3. 60日：同样显著落后则 `REJECTED`，否则 `FORMAL_REVIEW_READY`，停止新交易等待人工完整评审；这不等于通过晋级门禁。10个有基线快照的市场交易日后仍未处理，`REVIEW_EXPIRED` 归档。人工晋级操作入口尚待建设，不自动变更生产模型。
4. 缺少可信边界：`REVIEW_HOLD`，暂停而不是判定模型失败。可信起点来自首次评审时的point-in-time边界，并持久化到各候选；不同版本分别计数。

这是新增的可配置治理规则，并非Qlib原生淘汰算法；首轮应用已有历史时明确标注当前评审日期，不追溯声称预注册了历史实验。bootstrap并不保证策略有效，有限样本与多个版本共享数据的限制仍存在。风险、成本、漂移等完整晋级门禁没有被替代。

## 执行与审计

- 状态与评审写入 `state/candidate-lifecycle.sqlite3`，独立事务；重复运行幂等，较早交易日不可覆盖较新决定，终态不会自动复活。
- 每日候选队列执行前后都评审；冻结候选跳过推理及新计划，撤销未成交模拟委托。PaperBroker另在提交、撮合与恢复取消委托处拒绝冻结候选。
- 原模型、信号、报告、权益、委托、成交不删除、不重算。既有持仓保留，冻结不等于清仓；不虚构卖出，不释放不存在的现金。后续若建设正常减仓退出，应另用可执行日期、整手及T+1规则生成退出计划。
- 前台主视图只展示有效候选；归档中保留退出原因、评审日与历史详情，可从顶部勾选查看。图表不重新归一或重写任何历史数值。
- 启用配置在 `configs/qlib_challenger.yaml` 的 `candidate_observation_policy`。关闭开关不复活既有终态。

## 运维

预览：`.venv/Scripts/python.exe scripts/review_qlib_candidates.py`

应用评审并撤销冻结候选的未成交模拟委托：同命令加 `--apply`。不运行训练、不生成新交易、不发送真实委托。

原运行共同日保留供观察；可信评审日只统计边界以后三账户都有有效正权益的日期，剔除未来日期、非有限值与重复日。全局边界20261023导致首轮多数有效候选只有1个可信评审日，不把47个运行日冒充47个合格统计样本。
