## 2026-10-22 明确观察关联与回执差异核对

新增 POST `/api/desktop-execution/receipts/link` 及页面“券商回执关联与差异对账”。用户必须指定桌面计划、非空委托快照、精确券商委托编号和说明，并明确勾选仅观察确认。后端校验证券代码+已识别市场、方向、数量与计划一致，委托导出行内日期存在且不早于计划信号日。没有按股票或名称自动认领。计划不含经过实盘风控审核的价格，记录委托价格仅供后续回执一致性核对，不证明与策略意图或实盘风控一致。

关联保存在独立 `desktop_receipt_links` 表，一个计划至多一条关联，同一账户别名+交易日+市场+委托编号至多归属一个计划。重复相同关联幂等，冲突或改绑阻断，当前不支持拆单/子订单关联或自动改绑。关联创建不下单、不撤单、不改原模拟账本，不解除来源已变化保护；本地别名不是账户身份证明。

只读核对同一别名/日期的已保存快照：按文件时间顺序核对委托累计量，成交按精确编号去重；相同编号不同内容、证券/方向/数量/价格变化、累计倒退、最新表缺少历史已观察记录、汇总/明细量不一致等进入待复核。缺成交表为未知，不填0；旧空表不会清掉历史成交。仅识别内部观察到的部分/全额成交，`confirmed_filled_quantity` 始终未知，`broker_receipts_verified=false`，任何结果 `allow_resubmit=false`，不提供报单重试。文件mtime不是券商服务端时钟，人工改文件不能形成可靠的交易证明。

每条关联最多核对100份同范围快照，累计payload最多10MB，超限明确待复核而不当作空成交。核对只读且可跨服务重启恢复。市场字段仅明确映射已见过的上海Ａ/深圳Ａ，缺市场或行内日期的老快照不可绑定；解析版本纳入快照ID，新版本导入保留旧快照，不静默重写历史。

该阶段89项相关测试、目标页面类型检查和生产构建通过，包含非空文件导入→持久化→重启恢复→全部成交观察核对的合成闭环，全部非空回执测试仅使用虚构数据，未向真实客户端发送测试委托。当前真实委托为空，因此不生成任何真实关联。下一门禁仍是独立取新导出、账户来源证明，以及本账户既有非空买卖回执的只读验收。

## 2026-10-22 华泰导出快照接入

新增桌面执行页“华泰券商只读快照”：列出 `state/private/huatai-acceptance/` 中以 positions/orders/trades 开头的文本导出，通过 POST `/api/desktop-execution/exports/import` 显式读取文件、指定类型/数据日/本地账户别名。无需 Codex 或大模型参与解析，不激活券商窗口、不修改模拟交易账本。不支持上传、任意路径、目录穿越或链接到目录外；最多读取 5 MB，读取前后文件大小/mtime 不一致则拒绝。该入口使用与现有桌面操作相同的本地 Origin + 专用请求头防护，不是公网身份认证。

快照持久化在 `desktop-execution.sqlite3` 的独立 `desktop_export_snapshots` 表。按类型、账户别名、数据日、源文件内容哈希幂等去重，重复导入不刷新首次导入时间或源文件时间。页面同时展示文件时间、首次导入时间及数据日期；超过5分钟或数据日不是上海当日标为历史/过期，不把导入时间冒充券商实时采集时间。文件mtime并非可靠的券商服务端时间，近期文件仍标业务未核验。最近30份快照，每份最多展示100行；界面明确提示截断，完整内容保存在本机快照表。

解析保留编号前导零及真实零值；不保存导出中的股东代码列，不从股票反推来源策略，不将空表视为已验证空账户。所有快照 `account_verified/date_verified/broker_receipts_verified=false`，不更新原委托状态或盈亏。此次验收的真实样本为8条持仓、当日委托及成交各0条；非空买卖回执与唯一策略关联仍待验收。

## 当前范围与边界

2026-10-21第一阶段：已实现网页入口、独立本地只读代理、来源委托关联和隔离准备账本。不是已完成的真实交易系统。

链路：浏览器桌面执行页 → 本机FastAPI（仅监听127.0.0.1）→ 固定Python模块子进程 → 指定交易客户端的Windows UI Automation只读控件树。没有Codex、sky、API Key或大模型运行依赖。首次安装desktop可选依赖需要网络，日常代理不调用外部AI。

用户无需将交易客户端置顶；代理没有激活窗口、鼠标键盘输入或坐标回退功能。但后台可读取不等于后台可下单：自绘表格可能不提供可读控件。锁屏、认证窗口、UAC安全桌面、不可读进程和25秒读取超时均阻断。未实际验收某客户端前，不承诺可用。

普通券商PC客户端由用户自行下载、安装、启动和登录。网页填写已安装exe的绝对路径并保存只读配置，随后点击“后台只读探测”。没有自动登录、密码保存、验证码处理、启动任意命令或安装软件入口。

## 已实现接口

- GET `/api/desktop-execution`：准备计划、来源待处理委托和最近10个探测作业。
- POST `/api/desktop-execution/client`：配置已存在的exe，不启动它。
- POST `/api/desktop-execution/probe`：固定只读工作模块，25秒超时，同一服务进程不并发探测；无可读目标则报告阻断。
- POST `/api/desktop-execution/prepare`：选择一个模拟账户准备计划；不下单、不修改原订单状态。
- 所有POST要求本地Origin与专用请求头。前端代理仅为该路由转发这两项；不接受外部站点发起的普通跨站请求。仅适用于本机单用户；公网或多人部署前必须增加完整身份认证和授权，不能把Origin检查当完整认证。
- 没有submit/cancel、坐标点击、脚本执行、命令透传或券商凭证接口。

持久化：`state/desktop-execution.sqlite3`独立于`paper_orders.sqlite3`。只读打开原模拟库；保留来源账户、strategy_id、源idempotency_key及原始参数指纹。同来源同参数重复准备返回同一计划。来源撤销、成交或修改后，旧准备计划标记SOURCE_STALE；多个模拟账户不直接合并成一个真实账户。

源数据预览最多500条、准备计划显示最近200条。准备记录没有券商账户绑定、委托价格、资金权限或真实可卖检查，因此绝不可直接作为可执行真实订单。

## 回执证明规则（下一阶段，未实现）

必须区分：策略信号 → 风控后订单 → 桌面准备计划 → 已提交但未知 → 券商已报 → 部分成交 → 全部成交／拒单／撤单。截图上的按钮点击成功和本地模拟fills都不能作为券商成交证明。

至少保存券商账户匹配证明、交易日、客户端来源、稳定委托编号、股票、方向、委托数量、委托价格、状态、累计成交量、各笔成交编号与价格以及读取时间。回执需要关联source_order_key与desktop_intent_id；不同策略同一股票不能仅按股票名匹配。

若报单结果未知，不重试下单；先查委托和成交。如果无法唯一关联则进入人工复核。累计成交数量不得倒退，重复回执按券商编号去重；重启后先恢复未知记录。未实现解析前页面固定显示“未取得券商回执”，不显示虚假的0成交或已成交。

## 建设顺序

1. 本阶段：网页与代理只读链路、隔离计划、幂等与无抢焦点保护。
2. 指定普通客户端，用户从网页探测；验证后台控件读取账户、持仓、委托、成交。单纯控件清单还不算业务验收。
3. 客户端专用只读回执解析、字段类型与唯一关联、重启和重复回执对账；先用人工产生或已有记录验证。
4. 只在模拟环境做订单准备与异常演练。真实证券委托由用户提交，本阶段不建设无人值守真实报单。
5. 如果客户端只能前台鼠标操作，不能满足“不影响正常电脑使用”，应讨论隔离桌面运行环境或获准接口等外部依赖，不偷偷抢焦点。

## 测试与操作

使用：MoneyMore左侧“桌面执行” → 保存客户端exe路径（不启动）→ 后台只读探测 → 查看结果。已安装依赖并不等于已配置或已验收客户端。当前未配置目标普通客户端，不能声称真实控件读取成功。
