# 固定风格预算与执行可行性修复

## 已修的机制

- Qlib适配器新增显式 `style_limits`，按固定数值传入原生 `EnhancedIndexingOptimizer.f_dev`，不再从当日持仓反算上限。未提供预算、预算负值/非有限、列名不匹配、与旧递推参数混用均阻断。
- 旧的 `style_retention` 仅供明确指定的历史研究复现，输出标识 `LEGACY_RECURSIVE_RESEARCH_ONLY`。不删除旧证据、不让新版默认回退到75%收缩。
- 新分支 `style_fixed_budget` 不调用连续Phase-I去承诺执行可行。开盘直接在同一整数模型内检查资金、整手、科创板申报量、可买卖、费用、单股上限、20% L1换手和固定风格边界。无整数解仍阻断，不放宽上限。
- 独立审计不仅重建成交持仓及现金，也检查整个研究窗口的预算数值完全不变、没有重新出现递推参数。

## 数值修复不改变经济问题

当前安装的Qlib原生优化器把分数按股票波动率缩放，再优化 `超额收益 − λ×主动风险方差`。日收益使用小数时，收益/协方差的数值尺度可能影响ECOS求解精度；原生第二次尝试还可能去掉换手限制，旧出口复核因此阻断。

新研究模式提供可选的等价预处理：令正数 `u` 为原生分数缩放所用的波动率，传入 `Cov/u²`、`specific/u²` 和 `λ×u`。经原生分数缩放后，新目标恰好是旧目标除以 `u`，最优经济问题和所有约束不变。对照与修复分支同时启用，不通过改风险厌恶来挑收益。风险报告仍以原始日小数单位计算，历史模式默认保持原数值路径。

已加入同问题两种尺度解的一致性回归；仍保留原生求解事件与最终换手/风格独立核对，不接受因求解降级而超限的结果，也不宣称全部数值问题已根治。

## 本轮固定参照是什么

1010在窗口前没有候选预测记录，不能伪造训练/验证历史。因此本次是**机制修复对照**：首次同规则整数建仓时，根据当时已知的实际规划持仓冻结四项标准化绝对暴露，后续只按此预算执行；不乘75%，不根据本窗口收益调强度。初始规划与实际撮合必须匹配才继续。

这不是训练出的最优预算，也不代表首次持仓的风险合理；首次偏离较小的因子可能形成较紧边界，首次偏离很大的因子也不会因此自动得到治理。每个候选各有其初始参照，不把这种对照当成同风险预算下的正式晋级比赛。正式预算仍需事前定义基准、训练/验证样本、版本与滚动样本外验证，不能用本窗口表现反向选择。

## 运行

```powershell

.venv/Scripts/python.exe scripts/audit_integer_continuous_replay.py --fixed-budget
.venv/Scripts/python.exe scripts/attribute_style_replay.py --fixed-budget
```

单账户在前两条命令加 `--account candidate_20261010`；会写带账户后缀的新报告，不覆盖旧的75%研究报告。所有回放账本均新建UUID目录。固定预算的研究结果不自动写入生产模型、模拟盘、真实订单或历史权益。

产物前缀：`fixed-budget-continuous-replay`、`fixed-budget-continuous-audit`、`fixed-budget-actual-fill-attribution`。
